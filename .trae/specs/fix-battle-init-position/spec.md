# 修复战斗初始化位置错位问题 Spec

## Why
目前在战斗中，防守方的主将初始化位置存在错位，没有正确放置在地图正中心的城池中。经过分析，这是因为在从原版 C 代码移植到 TypeScript 时，遗漏了原版静态位置偏移表（`dFgtIntPos`），采用了简化的动态阵型计算。同时攻击方的初始基准坐标 (`sx`, `sy`) 也没有完全对齐原版逻辑，可能导致阵型超出地图边界或不够居中。需要完全还原原版的阵型排布，以保证武将初始位置正确、还原经典的战斗体验。

## What Changes
- 引入原版 C 代码中的静态阵型坐标表 `dFgtIntPos` 作为 `FGT_INT_POS` 常量。
- 修复防守方基准坐标的计算，结合静态坐标表，确保防守方主将精确落在城池所在坐标。
- 修复攻击方基于 8 个进攻方向的初始基准坐标 (`sx`, `sy`)，使其完全对齐原版 `FgtGetBaseXY` 的逻辑。
- 替换现有的动态 `getFormationOffsets` 逻辑，改为读取 `FGT_INT_POS` 常量进行偏移计算。

## Impact
- Affected specs: 战斗初始化模块
- Affected code: `src/core/battle/useBattleStore.ts`

## MODIFIED Requirements
### Requirement: 战斗系统初始化坐标
**修改前**: 使用简易的2排5列动态计算阵型，攻击方基准点固定偏移可能导致越界，防守方主将偏离城池中心。
**修改后**: 使用硬编码的原版 `FGT_INT_POS` 阵型表。防守方主将将准确生成在城池上，其他武将按原版阵型环绕。攻击方将根据进攻方向使用原版的基准坐标及专属阵型，避免越界且还原经典排兵布阵。
