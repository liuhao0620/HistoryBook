# 《三国霸业》复刻版 技术架构与开发指南

## 1. 架构目标与演进路线
本项目的核心目标是**完全脱离原 C 语言代码中的视图与逻辑强耦合限制**，采用现代化的“数据驱动”与“逻辑/表现分离”架构。
架构设计需同时满足以下三个阶段的演进：
- **阶段一（当前首要目标）**：完美复刻原版单机体验（使用纯前端架构跑通全部内政、战斗逻辑）。
- **阶段二（中远期目标）**：平滑升级为多人联机模式（状态同步/指令同步），无需重构核心逻辑层。
- **阶段三（长期目标）**：支持自定义剧本（MOD）与动态配置热更。

## 2. 技术栈选型
为满足“前后端逻辑复用（便于联机）”和“高性能渲染”，我们采用以下技术栈：
- **核心开发语言**：**TypeScript**。强类型约束是复杂 SLG 数值游戏的基础，且可以在浏览器与 Node.js(服务端) 间无缝复用 `Core` 逻辑。
- **UI 表现层**：**React** (或 Vue3)。负责渲染大地图菜单、武将列表、城市面板等复杂的界面交互。
- **2D 场景渲染引擎**：**PixiJS** 或 **Phaser.js**。专注处理大地图的拖动显示、16x16 战棋 Tilemap 渲染、以及技能粒子的特效播放。
- **状态管理**：**Zustand** 或 **Redux**。用于管理客户端的全局 UI 状态与游戏快照。
- **构建工具**：**Vite**。提供极速的模块热替换与打包能力。

## 3. 核心架构设计：MVC + 指令模式 (Command Pattern)

为了支持未来的**多人联机对战**，必须严格贯彻**指令同步（Command Sync）**思想。绝对禁止 UI 层直接修改底层数据。

整体架构划分为三个严格隔离的模块：

### 3.1 核心逻辑引擎 (Core System Layer)
这是游戏的“大脑”。**它不包含任何 DOM、Canvas 或浏览器特有 API**，完全是一个可以独立运行在 Node.js 环境中的纯逻辑黑盒。
- **配置管理器 (Config Manager)**：解析 JSON/CSV 中的静态数据（地形阻力表、技能威力、城池连接图）。
- **状态容器 (State Container)**：维护游戏当前的全部状态（年份、势力分布、城池资金、武将兵力等）。
- **指令执行器 (Command Processor)**：
  - 接收标准化指令对象（例如 `{"action": "BATTLE", "from": 1, "to": 2, "generals": [3, 4]}`）。
  - 执行合法性校验（是否当前回合？粮草是否足够？）。
  - 修改 `State Container`，并通过 `Event Bus` 向外抛出状态变更事件。
- **伪随机数生成器 (PRNG)**：
  - 联机游戏必须保证各端的随机结果一致。使用带 Seed（种子）的伪随机函数（如 LCG 算法）替代 `Math.random()`。确保同指令、同种子下，天气变化、暴击率 100% 同步。

### 3.2 视图表现层 (View Layer)
- **UI 组件树 (React)**：监听 Core 层抛出的事件，重绘数据面板。
- **场景引擎 (PixiJS)**：读取 Core 层的坐标状态，播放对应的移动动画或火攻特效。
- **输入拦截器 (Input Handler)**：将玩家的点击转化为合法的“指令（Command）”，发送给通信层。

### 3.3 通信与网络层 (Network Layer)
- **单机模式（阶段一）**：网络层作为一个本地的 Mock 代理，直接将 UI 层的指令压入本地的 `Core System`。
- **联机模式（阶段二）**：UI 层将指令发送给远程 Server，Server 仲裁后广播给所有 Client。Client 的网络层收到广播后，再压入本地的 `Core System` 进行推演。

## 4. 目录结构规划
复刻版项目的目录结构将严格遵循架构分层：
```text
src/
├── core/                # 核心逻辑层 (纯 TypeScript，前后端通用)
│   ├── models/          # 实体模型 (City, Person, Force)
│   ├── commands/        # 指令系统 (AssartCmd, BattleCmd 等)
│   ├── battle/          # 战棋引擎 (A*寻路, 伤害推演)
│   ├── state/           # 运行时状态管理库
│   └── utils/           # 工具类 (PRNG 伪随机生成器)
├── view/                # 表现层 (React UI)
│   ├── components/      # UI 组件 (城池面板、人物列表)
│   └── hooks/           # 状态绑定钩子
├── scene/               # 渲染层 (PixiJS 战棋与地图渲染)
│   ├── map/             # 大地图图块与连线渲染
│   └── fight/           # 战斗场景 (网格、角色Sprite、特效)
├── network/             # 通讯层
│   └── local_proxy/     # 单机模式的本地代理
└── assets/              # 静态资源 (图片、音效)
```

## 5. 如何支持自定义剧本 (MOD)
原版的武将数据、城市归属被硬编码在引擎中。复刻版将采用**完全数据驱动**的设计：
1. **剥离配置**：将武将属性、城市信息、剧本初始状态（如“黄巾之乱”、“赤壁之战”）全部提取为独立的 JSON 文件。存放在统一的 `config/` 目录下。
2. **动态加载**：游戏启动时，`Config Manager` 动态读取玩家选择的 JSON 剧本文件初始化 `State Container`。
3. **扩展性**：玩家只需要按照约定的 JSON 格式编写新的剧本文件，无需修改任何代码，即可实现自制 MOD（添加新武将、修改城市地图）。

## 6. 阶段开发路线图 (Roadmap)
- **Milestone 1: 核心基建与配置化**。建立 TypeScript 框架，编写所有 JSON 配置表，完成 `Core` 层基础数据模型的映射。
- **Milestone 2: 大地图与内政循环**。实现核心指令分发机制，跑通开垦、征兵、搜寻等内政操作的无 UI 单元测试。
- **Milestone 3: 战棋引擎推演**。完成 16x16 地图的 A* 寻路算法，实现计谋、地形、天气的伤害计算与回合判定。
- **Milestone 4: 渲染层接入**。结合 React 和 PixiJS，实现大地图可视化交互与战斗画面。
- **Milestone 5: 联机与剧本扩展**。分离 C/S 端，接入 WebSocket；开放 JSON 剧本加载入口。
